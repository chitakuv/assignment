# Android 系统级模块开发编译完整流程 和 产物

#### 1. 同步 AOSP 源码 + BSP (Board Support Package)版级支持包 补丁

- 拉下了 AOSP 原生系统源码（framework、system app 等）
- kernel、vendor 目录可能是空的，需厂商提供 BSP 补丁补全（驱动、HAL）

**操作示例：**
````
repo init -u [https://android.googlesource.com/platform/manifest](https://android.googlesource.com/platform/manifest) -b android-14.0.0_r1

repo sync -j8
````

#### 2. 设置环境 + 选择 Lunch 设备

- 设置交叉编译环境
- 选择目标设备，生成环境变量：
	- TARGET_PRODUCT
	- TARGET_ARCH
	- OUT_DIR

产物路径会自动设置为：out/target/product/<your_device>/

**操作示例：**
````
source build/envsetup.sh
lunch aosp_arm64-eng
````

#### 3. 添加/修改模块源码

- 在 packages/apps/、frameworks/、hardware/interfaces/、kernel/ 目录中：

- 添加系统 App（比如 Settings）或修改现有源码
- 修改 HAL 接口实现（如 camera HAL）
- 修改 framework 服务（如 ActivityManager）
- 添加设备驱动 .ko

 还没编译，不会生成产物。

#### 4. 按模块编译

- 编译刚 修改 或 添加 的模块
- 生成 .apk、.so、.ko 等中间产物

** 产物位置举例**

- .apk → out/target/product/xxx/system/app/Settings/
- .so → out/target/product/xxx/system/lib64/
- .ko → out/target/product/xxx/vendor_dlkm/lib/modules/

**操作示例：**
````
mmm packages/apps/Settings

make framework

make android.hardware.camera@3.5-service

make -C kernel/xxx modules  # 或 make modules
````

#### 5. 整体构建系统镜像

- 构建 Android 系统各个分区的 完整镜像
- 包括 boot.img、system.img、vendor.img、dtbo.img、recovery.img 等

** 产物目录：最终可交付的系统镜像**

	out/target/product/xxx/  
	├── boot.img           ← 启动镜像（内核 + ramdisk）
	├── system.img         ← Android 核心（framework + 系统 App）
	├── vendor.img         ← HAL / 驱动库（.so）
	├── product.img        ← Pixel 系 App 配置
	├── odm.img            ← OEM 专属驱动库
	├── vendor_dlkm.img    ← .ko 模块专用分区（内核模块）
	├── dtbo.img           ← 设备树 blob overlay  
	├── recovery.img       ← 恢复系统镜像
	├── .apk              ← 所有系统 App  
	├── .odex/vdex        ← dex 缓存文件
	├── root/              ← ramdisk 内容（init.rc 等）
	├── kernel/            ← 内核镜像/模块/符号表等
	└── obj/               ← 所有中间 .o 编译文件
	    └── obj/KERNEL_OBJ/vmlinux    ← 内核调试用，ELF 格式，只有开发者用

**操作示例：**
````
make -j$(nproc)
````


#### 6. 整体构建系统镜像

- 启动 Android 系统镜像
- 检查你编写的 HAL、App、驱动模块是否正常运行

对应日志输出：

- logcat → 打印 App 和系统服务日志（Java 层）
- dmesg → 查看内核日志（如驱动 .ko 输出）

**操作示例：**
````
emulator              # 启动模拟器  
fastboot flash xxx.img  # 烧录到真机  
qemu-system-aarch64     # 启动自定义内核 + rootfs.cpio.gz
````

# vmlinux 

`vmlinux` 是 Linux 内核源码编译后生成的「完整可执行文件」，包含所有代码、数据、符号和调试信息的 ELF 文件。

###### 作用：
1. **完整的 Linux 内核镜像**（未压缩、未精简）
    
2. **调试用的母体文件**（含函数符号表 + 段信息 + 行号）
    
3. **构建 Image/zImage/vmlinuz 的基础**



###### vmlinux 就像一个**内核的全图纸**，包含：


| 内容段     | 作用                                   |
| ---------- | -------------------------------------- |
| `.text`    | 内核的可执行代码                       |
| `.data`    | 初始化后的全局变量                     |
| `.bss`     | 未初始化的变量空间                     |
| `.rodata`  | 常量（比如 printk 的字符串）           |
| `.symtab`  | **符号表**，函数、变量名和地址对应关系 |
| `.debug_*` | **调试信息**，包括行号、变量类型等     |



**AOSP 编译系统默认不会把 `vmlinux` 放进最终产物目录。**  
- 它太大（几十MB）：

- 含有调试符号、不可启动
    
- 只供开发者做 crash dump 分析、符号定位
    
- 正常用户用不到，也没法烧录

它被编译出来了，**但被放在中间产物目录里**

你可以在如下路径找到它 (以 ARM64 为例）)：

	out/target/product/xxx/obj/KERNEL_OBJ/arch/arm64/boot/

里面有：

- `Image`（实际用于打包 boot.img 的）
    
- `vmlinux`（完整的 ELF 文件）
    
- `System.map`（符号表）
    
- `vmlinux.symvers`（导出符号）
